# Plan: Live-Text beim Diktat an der Insel (25.11.2026)

Anlass: Analyse A (Diktieren zu langsam), Entscheid Chief 25.11.2026 Punkt 4: «nur Plan, nicht bauen».
Status: geprüft (APPROVED Runde 3, Log unten). Wartet auf Entscheid Chief. Kein Code, kein Lauf beim Dienst.

## Ziel und Abnahme

Während die rechte Strg gehalten wird, steht der gesprochene Text schon da. Beim Loslassen wird er sofort eingefügt.
Heute wartet die Person nach dem Loslassen auf Hochladen und die ganze Transkription (bei AssemblyAI 1,5–3 s, nach
diktat-tempo etwa 1–2 s).

Abnahme (beobachtbar):
1. Stufe 1 (gegen ein lokales Socket-Doppel, das den Schlusstext 0,2 s nach `commit` schickt): Zwischen Loslassen und Text
   im eigenen Editor-Fenster liegen höchstens 0,6 s (Editor liest alle 300 ms). Gemessen am gebauten Paket wie bei
   1.0.16/1.0.17 (`lauf17.sh`). Stufe 2 (echter Dienst, nach Freigabe des Guthabens): Median höchstens 0,5 s.
2. Die Pille (bzw. die Pille am Pet) zeigt beim Sprechen die letzten Wörter, höchstens eine Zeile (~60 Zeichen).
   Kein Text erscheint ausserhalb der eigenen Fenster der Insel, bevor losgelassen wird.
3. Fällt der Live-Weg aus (keine Verbindung, Token abgelehnt, kein Schlusstext nach 0,8 s), kommt der Text wie heute über
   `/api/voice/transcribe`. Kein Diktat geht verloren, nie wird zweimal eingefügt; die Person sieht keinen Fehler, nur die
   gewohnte Wartezeit (plus höchstens 0,8 s im schlechtesten Fall).
4. «Nur Schweiz», «Sichere Cloud», «Eigene KI» und «Diktat auf diesem PC» (Schalter an, auch wenn das Modell noch fehlt)
   schicken nie Ton an ElevenLabs. Belegt durch einen Test der Weiche (rein, in `regeln.js`) und den Server
   (`realtime: false`, Token-Route 403).
5. Füllwörter, «Eigene Wörter» und «Letztes Diktat einfügen» verhalten sich wie heute.
6. Ein Kürzel mit der rechten Strg innerhalb von 0,28 s (z. B. Strg rechts + C) holt keinen Token und schickt keinen Ton:
   Der Token kommt erst mit der neuen Aktion `'gehalten'` (0,28 s gehalten) bzw. beim Freihand-Start. Wer länger hält und
   dann ein Kürzel drückt, hat schon einen Token; das Diktat wird trotzdem verworfen, Socket zu, `finish`. Neuer Quell-Test
   `insel/live-quelle.test.js` (Token-Aufruf nur im Zweig `'gehalten'`/freihändig) plus Test der reinen Regel. Im Leerlauf
   keine neue Anfrage.

## Stand im Code (geprüft 25.11.2026, Web origin/dev a3d919017 = main für diese Dateien)

- **Scribe Live ist da.** `src/lib/ai/voice-realtime.ts` (Token `POST /v1/single-use-token/realtime_scribe` Z. 119,
  WebSocket `wss://api.elevenlabs.io/v1/speech-to-text/realtime` Z. 150, nur dieser Host Z. 75), Route
  `src/app/api/voice/realtime/token/route.ts` mit `finish` (Verbrauch) und Rate-Limit (`request.ts`), Client
  `src/lib/ai/voice-realtime-client.ts` (PCM 16 kHz, `commit_strategy` manual, `language_code`; «final ~0,2 s nach Stopp,
  gemessen 09.11.2026»), Modell `scribe_v3_live` (`scribe-modell.ts`). Im Chat schon genutzt: `src/lib/voice/live-diktat.ts`,
  `ChatInput.tsx` — genau das Muster «Text beim Sprechen, fertig beim Loslassen».
- **An nur mit Schalter:** `realtimeVoiceEnabled` = nicht lokal, nicht Schweiz, `ELEVENLABS_REALTIME_ENABLED=true` und
  `ELEVENLABS_API_KEY` (Z. 23–27). Upstash-Redis für Sitzungen ist auf Vercel Pflicht (Z. 56–63). `/api/voice/status`
  meldet `realtime`; die Insel holt diesen Status schon alle 5 Min. (`insel.js` `lageHolen`, `stamm.sprache`).
- **Entfernt am 24.11.:** nur der ElevenLabs-Agent «Schnelles Gespräch (Test)» (Commit 10e8d9e9f, in main und dev:
  `voice-agent*`, `/api/voice/agent/*`, Fähigkeit `sprach_agent`). Das war ein ganzer Gesprächs-Agent bei ElevenLabs (STT,
  Modell, Stimme), kein reiner STT-Weg. Scribe Live ist davon nicht betroffen.
- **Hürde Herkunft:** `realtime/request.ts:8–14` nimmt nur Anfragen mit `Origin` gleich der App. Die Insel ruft die App aus
  dem Main-Prozess über `appSession.fetch` ohne `Origin` (`insel.js:393`) — der Token-Aufruf würde heute mit 403 enden.
  `/api/voice/transcribe` prüft das nicht.
- **Keine Wörter im Live-Weg:** Der Client schickt keine Keyterms. Scribe Live kann bis 100 Keyterms (+0,05 USD/h).
- **Protokoll** (`voice-realtime-client.ts:32,103,110,143`): PCM 16 kHz base64 als `input_audio_chunk`, Commit = leerer
  Chunk mit `commit: true`, Schlusstext als `committed_transcript`. Der Token steht in der Socket-Adresse (Query) — diese
  Adresse darf nie in ein Log.
- **Token-Antwort** `{ token, languageCode, websocketUrl, sessionId }`; `finish` erwartet JSON `{ sessionId, audioSeconds }`
  ≤ 1 KB (`finish/route.ts:10–19`). Eine Abbruch-Route gibt es nicht. Rate-Limit 30 Token je Minute (`request.ts:22`).
  Jeder Token schreibt einen Redis-Schlüssel und eine Zeile `logApiUsage` (`voice-realtime.ts:139,145`).
- **KI-Option frisch je Anfrage:** Die Token-Route liest die Option bei jedem Aufruf aus der Sitzung
  (`token/route.ts:12`); ein 5 Min. alter Status in der Insel kann also nichts freigeben, was der Server sperrt.
- **Pille:** `pille.html:5` hat `default-src 'none'` ohne `connect-src` — ein Socket aus der Pille ginge heute nicht auf.
- **Diktat-Start:** `aufnahmeStart` kommt schon beim Drücken, vor den 0,28 s (`regeln.js:36–40`, `insel.js:490–492`);
  ein Kürzel verwirft die Aufnahme danach (`'andere'` → `verwerfen`).

## Vorgehen

### Stufe 1 — Scribe Live an der Insel (Desktop + kleiner Web-Teil), geschätzt 4–5 Tage

Grundentscheid: **Der Socket läuft im Main-Prozess**, nicht in der Pille. Electrons Node hat `WebSocket` eingebaut. Die Pille
schickt nur PCM über IPC (32 KB/s). So bleibt der Token im Main, die Pille braucht keine neue CSP und keine Netz-Freigabe,
und der Schlusstext kommt dort an, wo eingefügt wird.

Spike zuerst (½ Tag): PCM aus der Pille. `AudioWorklet.addModule` von einer `file://`-Seite (Herkunft opak) kann scheitern.
Reihenfolge: Worklet-Datei im Paket; sonst Blob-URL (braucht `script-src blob:` in `pille.html`); sonst
`AudioContext({ sampleRate: 16000 })` mit `ScriptProcessorNode`. Erst danach weiterbauen.

Web (Branch ab origin/dev, Go von Chief):
1. Herkunft: Token- und `finish`-Route nehmen zusätzlich die Desktop-Hülle an — Kopf `x-space-insel: 1` **und**
   `sec-fetch-site` fehlt, `none` oder `same-origin`; ohne `Origin` nur zusammen mit diesem Kopf. Browser bleiben beim
   Origin-Vergleich. Ein fremder Browser kann den Kopf nicht ohne CORS-Vorabfrage setzen, und keine dieser Routen erlaubt
   fremde Köpfe (`Access-Control-Allow-Headers` nur bei `warteliste`) — der Schutz gegen CSRF bleibt. Vorher prüfen, welche
   Köpfe Electrons `session.fetch` tatsächlich sendet.
2. Keyterms: Die Token-Route gibt die Firmen-Wörter (Quelle wie `diktatWoerter`, höchstens 100) mit zurück; der Client hängt
   sie an die Socket-Adresse. In der Doku von ElevenLabs prüfen, ob das so geht, und die Länge der Adresse mit 100 Wörtern.
   Gilt dann auch für das Live-Diktat im Chat (`voice-realtime-client.ts` mit anpassen).
3. Preis im Code auf die heutige Liste (0,22 + 0,05 USD/h) und Quelle nachführen.
4. Tests: Kopf ja / fremde Herkunft nein / `cross-site` nein, Keyterms gekürzt, Schweiz/lokal weiter 403.

Desktop (Branch ab Giannino21x/insel-diktat):
5. Weiche, rein in `regeln.js`: `liveWeg({ realtime, lokalDiktat })` → `'scribe'` | `null`. `'scribe'` nur, wenn der Server
   `realtime: true` meldet **und** `lokalDiktat` aus ist — mit Schalter an gibt es nie Live-Text, auch wenn das Modell noch
   fehlt (wer «auf diesem PC» wählt, will den Ton nicht in der Cloud). Tests für jede Kombination.
6. Zeitpunkt: Heute entscheidet `regeln.js` «gehalten» erst beim Loslassen (`diktatHoch`, Z. 47–57). Neu gibt `takt`
   (Z. 79–88) einmal die Aktion `'gehalten'` zurück, sobald `zustand === 'gedrueckt'` und `t − seit ≥ HALTEN_MIN_MS`; der
   Freihand-Start gibt sie ebenfalls. Erst dann holt Main den Token (in der Praxis nach 0,28–0,38 s). Test für die Regel.
   Kürzel (`'andere'`), Esc, Verwerfen und stille Aufnahme (`pille:leer`, `insel.js:901–905`): kein Token; ist schon einer
   da, Socket zu und `finish` mit den gesendeten Sekunden.
7. PCM-Weg: Die Pille schickt PCM ab `aufnahmeStart` an Main, über einen neuen Kanal ohne Antwort (`ipcRenderer.send` /
   `ipcMain.on`, dieselbe Absenderprüfung wie `kanal`, mit `aufnahme.id` und laufender Nummer — `ipcMain.handle` mit
   `async` garantiert keine Reihenfolge). Main hält die Stücke in einer Warteschlange (höchstens 10 s). Öffnet der Socket,
   geht zuerst die Schlange, dann jedes neue Stück. Verwerfen leert die Schlange. Die Pille muss vom Token nichts wissen.
8. Main (`insel.js`): holt den Token über `api()` mit Kopf `x-space-insel: 1`, merkt sich `sessionId`, prüft die
   Socket-Adresse wie `voice-realtime-client.ts:28` (nur `wss`, Host `*.elevenlabs.io`, Pfad), öffnet den Socket (Protokoll
   portiert, gegen eine gemeinsame Liste der Nachrichten getestet) und schickt Zwischentext an die Pille (eine Zeile, auch in
   der Pet-Pille). Die Socket-Adresse (Token in der Query) kommt nie in `log()`, auch nicht bei `SPACE_INSEL_PET_LOG`.
   Test-Ersatz für Token und Adresse (Socket-Doppel) nur ungepackt (`!app.isPackaged`) und nur `ws://127.0.0.1`.
9. Bei der Aktion `'senden'` (Loslassen, ✓ der Pille, zweites Tippen freihändig, Zeitgrenze 6 Min.; `regeln.js:45–48,
   83–86, 104–108`):
   - Socket noch nicht offen → sofort Rückfall (kein Warten).
   - Socket offen → `commit`, auf `committed_transcript` höchstens 0,8 s nach `commit` warten (gemessen 0,2 s).
   - Bei langen Freihand-Diktaten (bis 6 Min.) prüft der Spike, wie lange ein einziger Commit braucht; wenn nötig Commit an
     Pausen.
10. Reihenfolge und nur einmal einfügen: Heute setzt `pille:audio` `aufnahme = null` und transkribiert sofort
    (`insel.js:869–870`). Neu: Ist eine Live-Sitzung offen, wartet der Handler von `pille:audio` auf den Schlusstext (Regel aus
    Schritt 9) und nimmt ihn; sonst geht die schon vorhandene Aufnahme an `/api/voice/transcribe`. Die Sperre über
    `aufnahme.id` bleibt; ein später Schlusstext nach Start des Rückfalls wird verworfen. `pille:audio` bringt neu `peak` mit
    (heute nur in der Pille, `pille-ui.js:209`). Rückfall auch bei Socket-Fehler, Token abgelehnt, oder Schlusstext leer bei
    `peak ≥ 0.004`. Der MediaRecorder läuft immer mit.
11. Danach: `finish` `{ sessionId, audioSeconds }`, dann `aufraeumen` (Füllwörter) und Einfügen wie heute.
12. Abschalten: keine neue Zeile im Blatt «Anpassen» in Stufe 1; aus über den Server-Schalter `ELEVENLABS_REALTIME_ENABLED`.

Prüfen: `npm test` (Weiche, Zeitpunkt, Sperre, Protokoll gegen ein lokales WebSocket-Doppel, `insel/live-quelle.test.js`),
dann am gebauten Paket mit Fake-Mikrofon und Socket-Doppel (Abnahme 1, 3, 6). Der echte Dienst erst nach Freigabe des
Guthabens durch Giannino (Stufe 2).

## Risiken und offene Fragen

- Ist `ELEVENLABS_REALTIME_ENABLED` und Upstash in Produktion gesetzt? Nur Giannino sieht das; ohne beides meldet der
  Server `realtime: false` und die Insel bleibt beim heutigen Weg (kein Schaden).
- Mundart: Wie gut ist Scribe v3 Live bei Schweizerdeutsch? Unbelegt — Stufe 2.
- Zwischentext auf dem Bildschirm beim Teilen: nur in der Pille, eine Zeile, wie bei Aqua. Option für später: aus im Blatt.
- Zwei Wege gleichzeitig (Socket + Aufnahme) erhöhen die Last kaum: PCM 16 kHz = 32 KB/s.
- Wechselt die Person die KI-Option während eines laufenden Freihand-Diktats (bis 6 Min.), streamt dieses eine Diktat zu
  Ende. Das nächste fragt den Server neu. Bewusst so gelassen, Stufe 1 schliesst es nicht.
- Die Token-Route nimmt nur die Wahl der Person (`providerFromUser`), nicht eine strengere Wahl der Firma
  (`providerForActor`) — wie `/api/voice/transcribe` heute. Eigener Punkt für das Web, unabhängig vom Live-Text.
- Rate-Limit 30 Token je Minute: Mit Token erst nach 0,28 s Halten reicht das für Menschen.
- Proxy: Das eingebaute `WebSocket` im Main (undici) nimmt den System-Proxy nicht, anders als `session.fetch`. Hinter einem
  Firmen-Proxy scheitert der Live-Weg immer; der Rückfall fängt das auf (nur die gewohnte Wartezeit).
- Gilt der Token-Kopf-Ansatz auch für den Handy-Chat? Nein, dort läuft es schon im Browser mit Origin.
